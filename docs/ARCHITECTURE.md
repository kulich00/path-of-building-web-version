# Архитектура и импорт PoB

## Поток импорта

Ожидаемый путь данных для кода сборки PoB:

```text
PoB-код → Base64URL → zlib → XML → модель сборки → интерфейс
```

На текущем MVP этот поток используется для импорта и отображения сведений о билде. Фронтенд реализован на JavaScript с React (`.jsx` для компонентов и `.js` для модулей). Lua-расчёты не входят в импортёр и пока не подключены.

Отдельным следующим этапом запланирован бэкенд на Go для вычислений и серверной логики. Его API и границы ответственности следует определить до реализации; текущий MVP работает без собственного бэкенда.

## Основные данные

Из XML экспорта извлекаются:

- класс персонажа, восхождение и уровень;
- выбранная группа умений и активный камень;
- предметы;
- версия дерева и выбранные узлы;
- данные mastery и кластерных самоцветов, если они присутствуют в экспорте.

## Определение основного умения

PoB хранит выбор группы и активного умения отдельно. Импортёр должен учитывать:

- `Build.mainSocketGroup` — выбранную группу;
- `Skill.mainActiveSkill` — активное умение внутри группы.

Выбор первого `Gem` в группе некорректен: первым может оказаться камень поддержки.

## Пассивное дерево

Данные узлов необходимо сопоставлять с TreeData версии, подходящей к версии дерева сборки. Узлы разделяются на отдельные категории:

- keystones;
- узлы выбранного восхождения;
- обычные пассивы;
- пассивы кластерных самоцветов;
- mastery и выбранные эффекты mastery.

Keystone определяется по признаку самого объекта узла в TreeData. Нельзя искать этот признак за произвольным диапазоном текста: соседний Lua-объект может ошибочно повлиять на классификацию. Узлы чужих восхождений не должны попадать в текущий билд.

Для кластерных самоцветов названия больших пассивов следует брать из данных самоцвета и добавляемых им пассивов. Динамические ID могут отсутствовать в основной карте TreeData; их нельзя выдавать за обычные неизвестные узлы.

Для mastery нужно связывать выбранный эффект с соответствующим узлом mastery и показывать название узла вместе с текстом эффекта, а не только числовые ID.

## Текущие ограничения

- Полные расчёты характеристик на Lua и сервис расчётов ещё не добавлены.
- Полная карта дерева с геометрией, связями, масштабированием и редактированием ещё не добавлена.
- Для неизвестных или динамических узлов интерфейс должен показывать понятное происхождение данных, а не придумывать название.

## Проверка импорта

Для ручной проверки используйте код из настольного PoB:

1. Сгенерируйте экспорт в Import/Export Build.
2. Импортируйте его в веб-приложение.
3. Сверьте класс, восхождение, уровень и предметы.
4. Убедитесь, что активный навык — выбранное умение, а не камень поддержки.
5. Сверьте версию дерева и категории выбранных узлов, кластеры и mastery.

Здесь следует добавлять автоматические тестовые фикстуры PoB и инструкции запуска по мере расширения тестового покрытия. Не включайте личные или приватные коды сборок без разрешения их владельца.
